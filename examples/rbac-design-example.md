# RBAC Design Example

## User Request

"Design roles and permissions for a B2B analytics app with owners, admins, analysts, and viewers. Include abuse cases and migration impact for existing users."

## Detected Task Type

Authorization and permission model design.

## Selected Workflow

`rbac-permission-design`

## Why This Workflow Was Selected

The request asks for roles, permissions, access control, authorization data modeling, and abuse-case review.

## Expected Output Structure

- Task intake card with actors, data boundaries, and assumptions.
- Actor inventory.
- Capability map.
- Permission model.
- Abuse-case and privilege-escalation review.
- Authorization data model notes.
- Migration and validation plan for existing users.

## Good Prompt

"Design RBAC for owners, admins, analysts, and viewers. Map actors to concrete capabilities, include deny cases and tenant/data boundaries, and describe migration validation for existing users."

## Bad Prompt To Avoid

"Create some standard roles and permissions for the app."
